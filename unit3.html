Unit 3: One Shot Game

My Catch the Falling Blocks Game

How I Created My Game

I started by asking AI to write a complete HTML file for a simple browser game. I asked it to include HTML, CSS, and JavaScript in the same file, use the HTML5 canvas to draw the game, and focus on one main mechanic. I also asked for comments explaining the setup, game loop, input handling, collision detection, and scoring.

The AI suggested a game called Catch the Falling Blocks. In this game, the player moves a paddle to catch blocks falling from the top of the screen. I used this game to investigate how HTML, CSS, and JavaScript work together to create an interactive game.

1. The Canvas

The canvas is the area where the game is drawn. In HTML, it is created using the <canvas> tag. JavaScript uses the canvas to draw the paddle and falling blocks and update their positions as the game runs.

The canvas has a width and height that determine the size of the playing area. If I change the width, the game area becomes wider or narrower. If I change the height, the playing area becomes taller or shorter. I would also need to check whether the game’s movement and collision calculations depend on the original dimensions.

2. The State Variables

State variables store the information the game needs while it is running. These can include the paddle’s position, the falling block’s position, the block’s speed, the player’s score, and whether the game is over.

These values are declared in the JavaScript section, usually using let or const. Variables that change during gameplay generally need to be updated as the game progresses. For example, the block’s position changes as it falls, and the score changes when the player catches a block.

3. The Game Loop

The game loop is responsible for keeping the game running. My game uses a repeating process to update the game and draw the current scene on the canvas.

A common way to repeat this process is with requestAnimationFrame(), which asks the browser to run the next animation frame. Another possible method is setInterval(), which repeats a function at a set time interval.

Each time the game loop runs, it updates the positions of objects and redraws the game. This creates the appearance of movement and allows the game to respond to what is happening.

4. Input Handling

Input handling allows the player to control the game using the keyboard. In a game like Catch the Falling Blocks, the player uses keys to move the paddle left and right.

JavaScript can detect keyboard input using an event listener, such as addEventListener("keydown", ...). When the player presses a control key, the code responds by changing a value or setting a direction that affects the paddle’s movement.

This connects the player's actions to what happens on the screen and makes the game interactive.

5. Collision / Win-Lose Logic

Collision detection allows the game to check whether the falling block has touched the paddle or reached the bottom of the playing area. JavaScript does this by comparing the positions of objects using conditions inside if statements.

For example, the code may compare the block’s position with the paddle’s position to determine whether they overlap. If the block is caught, the game can increase the score. If the block reaches the bottom without being caught, the game may end.

The exact comparison determines what happens next, so even a small change to a condition can affect how the game behaves.

6. Scoring

The score keeps track of how many blocks the player catches successfully. It is usually stored in a JavaScript variable, such as score, and displayed on the screen.

When the player catches a block, the code can increase the score using an expression such as score++ or score += 1. The game then updates the displayed score so the player can see their progress.

This rewards the player for successfully completing the main task of the game.

My Reflection

Creating this game helped me understand that a browser game is made up of several parts working together. HTML provides the structure, CSS controls the appearance, and JavaScript controls the game's behavior. The canvas provides the space for drawing, variables store information, and the game loop updates the action.

I also learned that keyboard input, collision detection, and scoring depend on conditions and calculations in the code. By finding these sections, I can better understand how the game works and how changing the code might change the player's experience.

My Next Step

If I were to improve my understanding of the game, I would experiment with changing the canvas dimensions, the block's speed, and the scoring rules. I would change one thing at a time and observe how it affects the game. This would help me learn through testing instead of only reading the code.
